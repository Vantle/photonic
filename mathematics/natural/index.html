Nothing, then one more.

A natural number is a finite quantity of indistinguishable units. Molten already has everything needed to represent one: an empty coherence, an ordinary concept, and orderless occurrences.

Formal specification · written mathematical arguments · recorded Rust checks

One atom is enough

Choose the ordinary concept Unit. A numeral occupies one root coherence containing only Units. Begin empty; add one fresh Unit at a time. Include exactly the presentations obtainable by finitely many such steps.

Names disappear. Quantity remains.

Occurrence identifiers help the runtime track resources. They are not part of a number. Reordering or consistently renaming occurrences preserves a numeral; changing its multiplicity changes the numeral.

Unitₐ · Unitᵦ≡Unitᵧ · Unitₓ≠Unitₐ · Unitᵦ · Unit𝒸

Subscripts above illustrate occurrence identity. They are not extra Molten syntax.

Formally, identify finite Unit particles under permutation and anonymous renaming, with no additional identifications. Zero is the empty class. The mathematical operation S adjoins one fresh Unit to a class. S is explanatory notation, not a language operator.

The crucial word is “exactly.”

A zero and a successor operation alone need not describe only the natural numbers: an arbitrary structure could contain unrelated extra elements. Our carrier is the least collection containing empty and closed under adjoining a Unit.

Why recursion is determined too

Choose an element z of any set X and an operation f on X. Send empty to z; send each successor to f of the preceding result. Every numeral has a finite construction, and every nonempty numeral has a unique predecessor class. This determines a map on all numerals. Induction proves that any map satisfying those equations agrees with it.

These are mathematical arguments about the specified carrier, using ordinary reasoning about finite constructions. They are not claims that Molten has checked a universal induction proof. The formal definition records the assumptions and boundaries.

The standard zero/successor interface and its induction and recursion principles are described in the Lean language reference. Here we realize numerical content with ordinary Molten particles.

Checking needs evidence, not a special type engine.

Prefix a candidate atom particle with one Check occurrence and use these two ordinary rules. Ask Obsidian whether the exact result Natural can be reached.

Check.Unit.Unit
[Check] Natural
[Natural.Unit] Natural
  1. Start checking. Check becomes Natural; the candidate Units remain.
  2. Discharge a unit. Each Natural.Unit interaction returns Natural.
  3. Establish the exact target. Natural alone leaves no numerical or unrelated remainder.

For zero, the first rule already reaches Natural. For any finite numeral, repeated unit discharge supplies a path. An unknown atom remains unmatched. Extra Check or Natural labels preserve too many control markers to equal the singleton target.

Source inference can also apply a later rule at an earlier concrete source. Such an edge may consume several source Units at once. It adds another justified event; it does not carry the intermediate Natural descriptions forward as extra operands. Distinct events can select different Unit occurrences and arrive at the same canonical state. Their event identifiers and inspected footprints distinguish those choices.

The input boundary matters

This protocol checks a flat atom particle under exactly these fixed rules, in one root coherence, with one Check added by the caller. Natural and Check are outside the numerical carrier. Supplying executable rule values or additional declarations changes the program and is outside this recognition interface. All these names remain ordinary user-defined concepts.

Obsidian's report is a reachability witness relative to that program. It is not an independently replayable certificate or a protected theorem-checking interface. An external “unreachable” report does not create a negative premise inside Molten.

A number is a quantity. A runtime state also has ownership.


One numeral forgets the names of its Units. Between coherences, shared introductions still matter. Two independently introduced Units reunite as two; one Unit inherited by two coherences reunites once.


The existing two-plus-three example uses independently introduced Left and Right coherences. [Left, Right] () consumes their control labels and rejoins five unmatched Units. Its independence precondition preserves the coherence contract. General arithmetic laws are outside this first formalization.
