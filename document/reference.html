Photonic reference laboratory

Rules transform concrete information. A derivation can reveal that a rule applies at an earlier source. That source gains an alternative outgoing event; intermediate descriptions do not become extra operands. Coherences evolve independently, and only a joint derivation can justify bringing them together.

The core execution model is implemented. The Rust runtime executes this model end to end from native source, with resumable matching and canonicalization, optional deterministic workers, and explicit resource accounting. This laboratory remains its independent JavaScript reference: all 20 examples cover concrete-source inference, joint inputs, multiple outputs, nested bodies, positive evidence, generated rule values, whole-rule abstractions, and lexical captures. Rust conformance tests compare the complete configuration and application-edge sets with support status for the 19 closed programs; one growing program remains suspended.

One evolving graph

A state is an orderless collection of coherences with their live occurrences, lexical environments, and return continuations. Occurrence identity records sharing: two copies of an inherited reference can denote one introduction, while two independently computed equal results remain two introductions. Particle multiplicity remains significant: A.A differs from A.

An event records a rule, its concrete binding, its result configuration, and its justifications. Direct matching is the identity derivation. An inferred match uses the same application operation, with a joint witness projected to a concrete footprint. Repeated evidence contributes support to the same event. It does not emit another copy of its result.

OperationConcrete behavior
Literal resultReplace the projected source footprint. Preserve unrelated source remainder.
Nested bodyConsume exact source matches; transfer the remaining concrete witness and unrelated remainder into the body. Record consumed context in its continuation.
Several outputsCreate fresh explicit results. Broadcast references to the combined remainder into each output coherence.
DecoherenceRequire one joint witness. Reconcile shared untouched introductions once; retain independent introductions separately.
State reuseCanonicalize occurrence names, coherence order, sharing, scope, and continuation. Reuse equal configurations while retaining distinct event support.

A consequential choice: with A → B.C and B → D, inferred application at A produces D; actual sequential execution produces C.D. These are distinct alternatives. Source inference is an additional language operation, not a claim that every evidence path can be replaced by an observationally equivalent shortcut.

Likewise, a joint match of sibling B and C can project to their one producer A. It need not invent two copies of A. Separate competing paths A → B and A → C cannot supply that joint witness.

Program representation


Matching gates


A gate is a useful implementation picture: partial matches arrive, compatible assignments accumulate, and a completed assignment enables an event. This resembles the incremental matching networks described by Forgy. His paper also describes count-based filtering and explains why retaining matched elements and their combinations avoids repeated whole-memory scans. Forgy, Rete (1982), §§1.2–2.


A semaphore counter is insufficient as the matching representation. For And.Boolean.Boolean, the two Boolean positions must receive two distinct current occurrences from a compatible witness. Receiving the same proof twice cannot fill both positions. Different substitutions, scopes, and incompatible histories must never be added into one count.

Both runtimes use incremental gates for coherence input positions. Each gate belongs to one joint witness configuration and frame; it retains slot candidates and compatible prefixes, including out-of-order arrivals. Completed bindings feed the existing source projection and event interning. Particle matching still enumerates literal occurrences. The JavaScript reference caches lazy matching gates. Rust advances particle candidates and gate extensions incrementally, caches each completed binding by target configuration, frame, and pattern, and delivers it to subscribed views. Candidate search storage is released when enumeration completes. Incoming/outgoing dependency indexes avoid repeated full-graph scans. Optional Rayon workers advance independent matcher and canonicalizer steps; one coordinator merges results in queue order. Maintain a set of filled positions for each compatible partial binding; a count can summarize that set. Reverse dependencies wake eligible concrete sources when evidence changes. Notifications travel through an index; recorded history is never physically rewritten.


Matching, propagation, and application remain one iterative semantic relation. An implementation may pipeline their bookkeeping and use queues or synchronization primitives without introducing a language-level search/commit phase. A fair queue processes newly discovered bindings and support changes. Unchanged candidates do not pulse forever.

Rules as values


Exact matching needs no decomposition. A complete nested rule can occupy one ordinary pattern position. Match the whole value, consume that occurrence, and produce the output by the same operation used for any other concept. Accessing a rule’s internal fields is needed only for a pattern that explicitly asks to match those fields. Being internally structured does not make a value multiple operands.


Implemented reference contract: represent a rule as an immutable structural value with its lexical bindings. Ordinary rules may match such values and produce new ones. The active rule index is derived from the rules visible in the current configuration; it is an optimization, not a separate global mutable program.


The chemical abstract machine gives a precedent for unordered reaction-based computation and a higher-order calculus. The join-calculus tutorial develops reaction definitions and lexical scope in a precise concurrent model. These are useful precedents for a small operational core, not evidence that Photonic’s proposed source-inference semantics already follows from either calculus. Berry and Boudol (1992); Fournet and Gonthier (2001 draft).


The notation below is explanatory, not Photonic surface syntax. rule(P,Q) denotes a whole rule value. In native source, [[A,B]] ([B]) consumes the rule with inputs A and B and no output, then enters a body containing the consuming rule [B]. It does not declare an alias.


R = rule(A, B)
M = rule(R, rule(A, C))

current:   { A, R, M }
rewrite:   { A, rule(A, C), M }
apply:     { C, rule(A, C), M }


The accepted interpretation is ordinary consuming replacement: M explicitly matches the rule value R and replaces it in the successor. The earlier state still exists and may have its original alternative A → B. This is local program evolution. A global alias that makes two expressions interchangeable everywhere would be a stronger semantic commitment.

Implemented semantic decisions


The closure contract records the accepted reasoning and acceptance matrix. The finite dynamic reference now implements the core interactions together. The accepted core closure and its explicit future boundaries are listed below.

A literal inferred result removes C and preserves the concrete source outside C, including R minus C. If one source supplies both roles, consumption wins.

A nested frame retains its executable closure without inventing a consumable R or turning its read dependencies into held consumption.


Rules remain local values


Expose a produced rule in an active coherence or lexical environment to make it eligible. Its rule value and arguments must have a compatible joint witness. A coherence supplying only read support stays in place; only input-bound coherences contribute leftovers. This preserves the parallel-context contract.


Capture immutable defining environments. Moving code preserves that capture; invoking it supplies a separate return continuation. Replacing a definition creates a successor value or environment, leaving historical closures intact. Canonical identity includes code, captures, sharing, and multiplicity. It never attempts to decide arbitrary equivalence of rule behavior.


Abstractions remain computation


Keep whole-value matching primitive. A rule can derive an abstract description of another rule and apply that description at the concrete source through the same mechanism used for True → Boolean. No mandatory decomposition or separate meta pattern matcher is required. No capture variables or named constructors are implemented. Arbitrary field extraction still requires a demonstrated encoding through the original rule model.


Applications require positive evidence


An application requires a concrete joint witness for its inputs and the availability of its rule. Exploration only adds evidence. Failure to find a value never enables an application; Not, True, and False are ordinary user-defined concepts.


Source notation must distinguish value and body


There is one grammar: concepts, dots, commas, brackets, parentheses, and whitespace. [Seed] [A] B produces a rule value; [[A] B] C consumes one; [Enter] ([Payload] Result) enters a scope. A missing output produces no coherence; () explicitly produces an empty one. No @, $, arrow, semicolon, brace, constructor, or absence-keyword syntax remains. See the frontend contract.

Semantics and implementation boundaries


The reference evaluator uses complete configurations to prevent accidental mixing of competing histories. Relative flow maps connect witness occurrences to source occurrences. Canonicalization preserves sharing while renaming anonymous introductions. Fresh equal outputs remain distinct, but a finite A ↔ B cycle shares two configurations.


The runtime computes positive evidence only. An unfinished exploration can leave a reachability question unknown. An external checker may report a target unreachable after finite closure, but that report is never a premise for a rule.


The intended completeness claim is fair discovery of every finite enabled derivation with sufficient resources. It does not guarantee termination. The laboratory limits state count, coherence count, live resources, frame count, and scheduled work; reaching a limit leaves deferred work available for resumption.


Both implementations deliberately preserve exact finite behavior. Rust uses interned atom names, recursive captured values, shared immutable states and views, binding caches, and adjacency indexes. Canonicalization visits symmetric permutations incrementally to avoid storing the entire permutation space, but worst-case time remains factorial. Rust refines the graph using resource sharing, captures, lexical links, and return links before enumerating unresolved symmetries. Matching and canonical ordering advance in resumable steps. Positive evidence is closed over recorded dependencies and cached until execution changes the graph. Parsing, graph setup, closure-environment normalization, and reporting are not strictly preemptible; record accounting is not a byte cap. Any such optimization must preserve the reference’s observable events and support, including alternative paths that source inference makes distinct.


Physics motivates locality and explicit causal accounting. It does not uniquely select this rewrite algebra, determine whether rules are persistent, or prove the source-projection convention. “Coherence” and “decoherence” are Photonic terms; the model does not implement a quantum state space or physical quantum decoherence. Configuration and event-structure research supplies the more direct mathematical comparison for joint availability and causal alternatives. van Glabbeek and Plotkin (2009).


Rust now provides the executable native frontend and integrated graph runtime, alongside the independent structural parser and generic multiset kernel. The runtime matches and produces whole rule values, preserves lexical captures, and applies abstractions at concrete sources. Arbitrary structural extraction, binding encodings, induction, behavioral equivalence, persisted checkpoints, and incremental program edits remain research work. The reproducible benchmark measures 19 finite programs; small-case timings do not establish unrestricted scalability. This configuration model supersedes the earlier single-result ownership experiments.
