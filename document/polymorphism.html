One matching mechanism,
from direct to derived

A direct match is a derivation with zero steps. A derived match follows rules to the required concept while retaining the concrete information that justified it. This is the candidate unification explored here; the examples do not introduce a separate type-rule syntax.

Physics motivates the questions about causality, retained information, and compatible histories. These experiments make the proposed computational answers explicit so we can test where the analogy fits.

What these examples narrow down


    

  1. Direct and derived matches share one definition. Find a rule path from supplied information to the requested pattern. Exact matching is the empty path.
    2. 

  2. Matching preserves its evidence. Not.True can satisfy Not.Boolean and still supply True to the nested body. A second derivation does not mint a second witness.
    3. 

  3. Continuation uses the concrete binding. The selected body performs the change. Whether and how intermediate rule applications can also be committed as ordinary flat computation remains to be specified.
    4. 

  4. Context must have an explicit scope. The examples pass unmatched Extra into the body and carry it to the result. This is a proposed behavior, not an accepted general scope law.
    5. 

  5. Matching needs compatible, distinct witnesses. Two independent Boolean inputs need two eligible occurrences; two proof paths about one occurrence are insufficient.

The laboratory deliberately implements a finite fragment: label-to-label rules, preserved context, simple derivation paths, and a supplied continuation. The body is shown as a dispatch table to test the intended example; this does not settle the meaning of brackets, nested rule installation, or rule selection in Molten.


The two-input example assumes distinct compatible coherences and shows separate input slots. A dotted particle containing two concepts is a different structure and is not modeled as two coherence inputs.
