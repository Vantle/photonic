# Structural construction reference

The independent Rust model in [model/](../model/model.rs) begins the executable semantic work required by [dynamic.md](dynamic.md) and the [recursive value contract](collection.md). It has no production frontend, matching, storage or proof-engine dependency. Build and run it through the pinned Bazel toolchain:

```sh
bazel test -c opt //model:test
bazel test -c opt //model:conformance
```

## Structural boundary

The model distinguishes Value, Particle, Input, Destination, Output, Body and Rule. Particles, inputs, outputs and bodies canonicalize their unordered contents while retaining multiplicity. An input containing one empty particle differs from an empty input. An empty output differs from one empty destination, and an absent body differs from a present empty body. Types prevent an input configuration from being substituted directly into a value position.

A contextual Rule names its lexical context. Nested rule values and bodies retain their own context references. Concrete contexts are nominal identities supplied by the model fixture; equal syntax in two distinct contexts remains different code. Deferred declarations additionally distinguish locally bound contexts from captured identities, as described below. Canonicalizing concrete context graphs under administrative renaming remains open.

Fragment carries immutable structural content and evidence. Its constructor is private to the model. Inspection of a concrete occurrence adds its read identity and reachable contextual dependencies. The construction API creates typed composites from fragments, unions their dependencies and preserves nested captures. Repeated code description insertion may duplicate syntax positions but retains the same read identity; it does not produce or transfer an additional live resource.

Opening a rule returns its input and output fragments plus a private origin. Closing that inspection reconstructs the original lexical context. Even replacing both visible components retains the origin's read and history dependencies. Constructing a new outer rule instead uses the construction context. These are different operations, including when their output text would look the same.

## History assumption

The first model uses explicit finite branch assignments. A history maps each named fork to one alternative. A construction may use a source only when its current history includes every source assignment with the same alternative. A missing assignment is insufficient evidence, and a different assignment is a conflict. Extending an assignment is immutable and rejects attempts to replace an existing alternative.

This is an explicit restricted compatibility model, not an implementation of Photonic's full source inference or grounded proof support. Configuration checks reject duplicate identities within a particle, inconsistent shared occurrences, dangling context references and inadmissible occurrence histories. The fixture still supplies the underlying identities, context graph and branch assignments; these checks do not validate arbitrary external proofs. Deriving assignments from production events, checking competing event histories, deriving general proof support and admitting arbitrary historical or inferred construction witnesses remain separate work. Checked finite projection and capture import are described below.

Evidence retains each inspected occurrence's identity, complete value and history, plus contextual dependencies and the current branch assignment. Its read-ID view is derived from those witnesses. Combining evidence rejects inconsistent descriptions of one occurrence, including during quotation and suspended construction. It intentionally retains conservative dependencies rather than minimizing them. Rule reconstruction must not erase a dependency just because a source component becomes empty or is replaced. Unknown atoms remain literals; there is no spelling convention that turns them into variables.

## Tested laws

The first suite checks arbitrary role/payload spelling, construction from inspected role and nested-rule payload occurrences, exact reconstruction through depth 16, distinct empty forms, permutation and multiplicity, mixed contextual insertion, body origins, output replacement and retention of a private origin when both components are replaced. A 729-pair history matrix independently checks assignment inclusion and inspection admission. Host-driven structural construction exercises depths 0, 1, 2, 3, 8, 16 and 32.

Host-driven generation demonstrates that the model representation can grow new structures. The staged model below additionally represents and evaluates generator factories. Neither establishes native structural execution, a runtime-recursive Photonic generator or a collection library. The construction operations remain atomic reference primitives; the machine below adds resumable template traversal. No universal preservation proof is claimed from finite tests.

## Binding and templates

Scope allocates typed slots with a nominal lexical owner and a unique position within that scope. Literal atoms never become references by convention. Binding stores immutable fragments under slots of one structural sort; immutable nested environments retain access to ancestor slots, reject attempts to bind an ancestor from a child, and reject reuse of an active scope identity. Rebinding an occupied slot is an error. A reference to a missing slot or inaccessible scope produces a structured failure.

Templates distinguish literal construction from references at each supported sort: value, particle, input, output and body. Building ordinary rule structure uses the current construction context. Building a body introduces a fresh local context binder for its declarations; activation supplies that binder's concrete frame. Substituting a captured fragment retains its original context and evidence at every sort. Every reference is checked against the current construction history before insertion. Sealing rejects unbound local references before publishing executable code.

The template suite checks unknown roles and contextual payloads, administrative renaming of binder scope identities, ancestor access and child isolation, duplicate binding rejection, missing external references, all supported structural sorts, body capture retention and history rejection on substitution. Repeated substitution preserves syntax multiplicity without manufacturing distinct source reads. One fixed template wraps increasing depth through 32 host-driven instantiations.

## Generated bindings

The staged construction model represents a generator as a declaration of future typed parameters and a term. A term either builds a closed value or quotes another generator definition. Parameter declarations support all five binding sorts, reject duplicate positions and foreign owners, and preserve literal atom semantics. Quotation validates references through every nested definition: references owned by an enclosing future declaration may remain unresolved; every external reference must resolve in the captured environment and pass the current history check. A reference with an undeclared position is rejected even when its owner is a known future scope.

A closed generator captures an immutable environment and the evidence needed by its external references. Application supplies exactly the declared parameters with their exact sorts in a private nested environment. All argument and generator dependencies are retained, including for an argument the body does not use. A quoted child captures its parent's now-bound parameters while retaining its own unfilled future parameters. Separate invocations of one factory can therefore produce separate builders without exchanging bindings, histories or payload captures.

The factory test represents a generator whose role parameter becomes the input of a generated field builder. The returned builder owns a new payload parameter; applying it creates ordinary closed rule structure. Two invocations retain different roles, while a nested rule payload retains its own lexical context and source identity. Further tests cover binder renaming, missing external and undeclared local references, duplicate/foreign/mismatched declarations, all parameter sorts, arity, ancestor histories, nested capture evidence and inactive future evidence at quotation time.

Generator products belong to the reference construction machinery, not to live Photonic configurations. This is a staged semantic experiment with explicit quoted definitions, not production syntax or a second native callable value kind. Scope identities in fixtures are nominal; invocation behavior is tested under their renaming, while canonical equality of quoted code remains unimplemented. The application model below supplies direct matching, ownership and fresh declaration binding, including construction through typed templates. Qualified generator products now connect to checked publication and inferred execution through the staging integration below; the general structural commuting law remains open.

## Concrete application

Configuration holds worlds, frames, a distinguished retained root and one compatible history. A request names executable code and explicitly selects the occurrence identities for each input particle. It is a direct application checker, not a search engine. Selected worlds must be distinct and share an execution frame. Values match exact closed structure, including nominal captures. Within a particle, positions require distinct occurrences. Across distinct worlds, a joint match may select the same shared introduction; consuming it does not create independent resources.

A live rule must occur in a participating world and contributes an executable read. A declaration must be visible through the execution frame's lexical chain; a parent return link does not grant lexical visibility. Lookup terminates even on a cyclic fixture graph. A declaration's return owner is its containing frame, while a live closed rule retains its captured owner. Applying code owned by the current child frame returns to that frame's parent. Inherited code continues in the current frame.

Application removes consumed introductions from participating worlds, unions the remaining occurrences by identity and gives each output the same shared remainder. Explicit output positions receive fresh occurrence identities, including equal sibling outputs. Untouched worlds retain their contents. Each event records reads, consumed places and resource, world and frame maps. Fresh resource flow depends on consumption and any held returning resources; executable reads remain separate support. A body enters a fresh frame with its declared lexical context and reserved consumption. Closed nested values keep their own captures. Reachability retains captured frames and follows parent, lexical, declaration and held-value dependencies; unreachable frames and their target flow entries are reclaimed. Allocation remains fresh along a configuration lineage after reclamation and reports checked exhaustion only when allocation is required.

The declaration representation separates return ownership from embedded captures. Ordinary executable structures use concrete context identities. The same structural constructors can represent deferred declarations with context references: Captured retains an existing identity, while Local names an enclosing body binder by depth. Local(0) denotes the nearest body activation. A nested body's declarations introduce another binder; its lexical context expression belongs to the surrounding scope. Local references are typed separately from executable identities.

Body.bind validates every local reference before sealing a contextual body. An out-of-scope reference fails with a structured depth error. On activation, the body's binder resolves to the newly allocated frame. References to it inside deeper bodies become captured identities, while references to those bodies' own future binders remain deferred. Particles, inputs, outputs and nested declarations are sorted after substitution. Captured references remain unchanged, including when their numeric identity happens to equal a newly chosen owner. Body.new embeds already closed declarations; activation.capture embeds closed rule structure without making its captures local.

These operations give a compositional substitution rule: replacing a particular body binder changes only references to that binder. Descending into a nested body increases the binder depth; descending into ordinary nested rule values does not. Sealing checks that every local reference has a corresponding binder, and activation produces executable structures with concrete contexts at the active level. The preservation argument still needs integration with construction evidence and source-inferred projection; no general production simulation is claimed.

Seven activation tests cover fresh versus captured contexts, nested outer references, imported bodies, invalid depths, context evidence and reconstruction, depth families through 32, and actual execution of locally emitted and imported closures with different lexical results. The depth family also checks that embedding and reactivating closed code preserves its structure at every level. A native comparison imports a ground source fixture into the reference representation: a local declaration emits code, returns, and later calls that code through its retained local frame. The result selects the local A declaration despite a competing root A declaration. The test adapter shares the frontend's parsed source representation, but does not use the native matching or rewrite implementation to derive the reference result.

Construction now supports typed deferred fragments while retaining its private evidence origin. Deferring ordinary construction captures its current context; entering local declaration construction changes the syntactic binder without discarding that origin. Lifting an inserted closed fragment preserves all captures, reads and history dependencies. Sealing returns a closed structural sort only after checking binder scope. A local rule fragment cannot be sealed directly as executable code; it must occur beneath its body binder. The explicit closed-declaration body constructor still embeds already captured definitions, while template Body.Build creates local declarations.

Six declaration integration tests compare recursive and resumable construction with evidence retained. A mixed local/imported closure fixture resumes at every suspension boundary, checks its introduction against the original live witnesses, activates and executes both closures, and checks their different lexical results. Further tests cover missing bindings and competing histories at every suspension boundary, all five inserted fragment sorts inside local declarations, refusal to publish an unbound local rule, generator invocation, and nested body construction and activation through depth 32. The native escaped-code comparison checks both direct structural import and templates constructed one machine step at a time. Introduction has the concrete admission boundary below; inferred and historical witnesses still need their own law. Activation, capture conversion and sealing remain atomic reference operations.

Thirteen application tests cover exact matching, multiplicity, shared and fresh ownership, code locality, empty inputs, scoped reservation and return, lexical visibility, captured owner behavior, historical results after code consumption, invalid configurations, capacity and repeated reclamation. Their raw configuration fixtures isolate application semantics. The declaration integration tests additionally use checked construction introduction. Application itself is atomic and has no production work-accounting claim.

The separate conformance target depends on the native engine; the model library does not. A 27-case matrix varies consumed multiplicity, output branching and retained multiplicity, comparing output values and occurrence sharing with direct native execution. Further cases cover a live executable read, a joint match consuming one introduction shared across worlds, a scoped declaration return and escaped local code. The matrix also checks that a shared remainder does not satisfy a complete target requiring distinct fresh copies. An additional scoped-return case compares complete composed resource, world and frame maps with a supported native view. These are restricted ground comparisons, not arbitrary contextual graph equivalence, general flow-map conformance or source-inference preservation.

## Introduction and flow

The [introduction operation](../model/introduction.rs) publishes one completed fragment into one concrete world. It checks the configuration's history against the fragment, requires every recorded contextual dependency to exist, and compares every read witness with its complete live occurrence in that world. Matching an ID alone is insufficient. Consumption is explicit, requires distinct existing occurrences and may overlap reads. The operation gives the new value a fresh identity, preserves the unconsumed remainder and captured code contexts, and records reads, consumption, contextual support and flow. Capacity or admission failure leaves the source configuration unchanged.

Introduction is a reference construction transition, not an ordinary rule firing or new native syntax. It creates a fresh occurrence of completed code description; it does not silently transfer an existing occurrence's identity. Its resource flow follows explicit consumption, while inspected code and data remain separate read support. The selected world supplies a context dependency even when both reads and consumption are empty. A later application can read the introduced code and consume its arguments through the ordinary application model.

This first introduction boundary requires live witnesses in the selected world. It does not yet admit witnesses available only through another coherence, held resources, an earlier supported event or source inference. An already introduced result survives later consumption of its source reads. A retained fragment can use the separate checked historical admission below when the required prior-world witness and checked contextual dependencies are available; direct introduction still requires live reads. Configuration contexts and branch assignments remain nominal fixtures; the model is not an external proof checker or a proof that arbitrary construction programs followed the intended operations.

The independent [flow implementation](../model/flow.rs) constructs identity maps, validates exact target domains and existing source references, projects a selected resource basis, and composes resource/world relations and optional frame origins. An absent frame origin stays absent through composition. Missing intermediate entries produce structured failures rather than silently dropping dependencies. Domain validation checks map shape, not the semantic justification of its edges. Resource projection alone is not inferred matching: it neither establishes exact consumption nor carries all event read support. A composed resource map cannot replace the supporting event chain.

Four flow tests include all 4,096 triples of two-by-two resource/world relations and all 729 triples of two-frame optional origin maps. Independent path enumeration checks the result; associativity, identity, empty-world context retention and malformed-map rejection are also covered. A native scoped-return fixture checks that held consumption composes back to its original resource while an unrelated remainder retains identity. Six introduction tests cover construction followed by execution, read/consume overlap, empty consumption, witness mismatch, conflicting evidence, history/context admission and allocation failure. Conflicting evidence is additionally checked across every construction suspension boundary and at quotation. The mixed-capture integration fixture uses checked introduction after every construction suspension boundary.

## Resumable construction

Machine interprets a template through an explicit task stack, visiting one child at a time and retaining private partial composites. Each task transition consumes one model work unit. `run(0)` leaves unfinished construction unchanged. Entering a declaration body saves the enclosing construction context; completing that body restores it before assembly continues. A successful result is published only after the complete outer value is assembled and sealed; a failure is terminal and discards partial work. Further calls after either outcome preserve the outcome and consume no additional work. Borrowed immutable templates and environments, an immutable sealing context and private deferred construction state prevent external mutation beneath a suspended cursor.

The recursive template interpreter remains the independent traversal oracle. Machine tests compare both success and structured failure at every single suspension boundary for empty shapes, nested code, branching particles, bodies, references and missing or incompatible bindings. They also compare repeated budgets of 1, 2, 3, 7 and 32 work units and repeated observation after completion.

These work units specify reference-machine progress, not production runtime step accounting. Fragment cloning, dependency union, multiset sorting, capture conversion and final sealing still occur within individual primitives. Final sealing traverses the assembled structure atomically. Consequently this is cooperative resumability between structural operations, not a wall-clock preemption or hard-memory guarantee. Native integration must separately account for those primitive costs, code/environment limits and production observation compatibility.

An invocation that produces a closed value uses the same machine and retains generator and argument support in its final result. Suspension-prefix tests compare this path with direct invocation, including unused-argument evidence. Quotation validation and parameter preparation remain atomic reference operations; the machine API explicitly rejects a quoted-generator term rather than pretending its validation has been budgeted. Resumable quotation is still required before production integration.

## Checked paths and projected bindings

[Path](../model/path.rs) starts from a valid fixture configuration and replays explicit direct application, introduction, inferred application or historical admission requests. Each extension reruns the corresponding semantic operation, checks its flow endpoints and composes the accumulated flow. Its states, records and composed map are immutable to callers. A record preserves its request, immediate flow, reads, consumption and contextual support; record position identifies its source and target states. Projection accepts this checked path rather than an arbitrary caller-supplied flow. The initial configuration remains a premise, and finite reference replay is not a general external proof checker.

[Projection](../model/projection.rs) first validates a concrete match at the path endpoint. A local executable must occur in a participating endpoint world. A declaration belongs to the source state and must be lexically visible at the projected execution frame; captured input values are mapped into the witness context before matching. Distinct input particles require distinct witness worlds even when their origins project to one source world. The selected endpoint frame must have a source origin, every contributing source world must belong to that source frame, and a consuming footprint that reaches a held place is rejected under the current native projection contract.

The binding separately records the broader footprint, exact sources and executable reads. Every selected witness contributes its consuming basis to the footprint. A source is exact only when that basis is one ordinary source occurrence and its complete value agrees after capture mapping. A freshly regenerated equal value can therefore be exact, while a differently captured value is not. A generated executable contributes the basis of its read occurrence, independently of argument consumption. Its captured owner may have no source-frame origin; the binding preserves that fact for capture import rather than substituting a root owner.

For `Seed.A [Seed] [A] B`, matching the generated code on A projects consumption to A and executable reads to Seed. Earlier reads used to produce that code remain in the checked path. Two paths can have identical endpoint states and resource maps while retaining different read support, so the projected binding alone cannot replace the path. The Projection object keeps an immutable reference to that path and its concrete request.

Eight tests cover replay and failed extension, seedless requests, exact versus derived values, differing captures, retained reads despite equal flows, checked introduction in a path, held-footprint rejection, unmapped execution frames, source-frame disagreement and empty input. Three native test families add six cases comparing supported event footprints, exact sources and reads: changed derivations, equal regeneration, two witness worlds from one source world, multi-resource production, generated code and an escaped owner requiring import.

## Projected application and capture import

Projection now applies its checked binding to the source configuration through the same [rewrite operation](../model/rewrite.rs) used by direct application. Each ordinary destination removes the broader consuming footprint; each destination with a body removes only exact sources and reserves those sources with any held resources consumed by a return. Mixed scoped and ordinary destinations therefore compute their own remainders. Explicit output values depend on the broader footprint plus return consumption. Executable reads remain separate support. Untouched worlds, shared remainders and fresh output identities retain their existing contracts.

The [import operation](../model/import.rs) discovers the complete captured graph needed by executable code, allocates every new frame before reconstructing edges, and remaps captured references inside inputs, outputs and deferred declarations. It preserves local binders. Existing frame origins reuse the source environment; absent origins receive fresh identities. Discovery includes imported declarations, lexical and return parents, and held values. A mapped outer code owner does not excuse importing an embedded unmapped capture. The resulting rewrite reclaims frames unreachable from the result and validates its flow endpoints.

Held import preserves a source occurrence identity when a singleton basis carries the same complete value, mapped captures and history. Other held values receive fresh identities, shared consistently across imported frames. If several held witnesses map to the same source occurrence, import retains one occurrence and unions their flow bases. The regression fixture `A.Call [A] A.A [A.A] (Make [Make] [Call] [Payload] Result)` exercises that convergence through a checked reference path. Reconstructed configurations must still satisfy the original occurrence-identity invariant.

This investigation found the same duplicate-identity defect in the native import primitive. Its old implementation appended both remapped held tokens and allowed the final flow map to overwrite one basis. [The native regression](../language/test/import.rs) supplies two held witnesses of one source occurrence shared across two worlds: the corrected import retains one token and both source places. This is an intentional correctness correction to held import, not a runtime speed claim. The fixture tests the application primitive; bounded native exhaustive exploration of the growing reference program above did not reach the corresponding event and is not reported as end-to-end native validation of that program.

Two new core test families cover mixed scoped/ordinary consumption, repeatable immutable application, exact versus derived held identity, imported declaration graphs and a mapped outer owner containing an unmapped capture. The six existing native projection cases now also compare resulting particle values, occurrence sharing and complete scalar resource/world/frame flow. Two scoped cases compare held counts, frame parents, lexical links and complete flow. An escaped-code case checks the inferred result and execution through the imported local declaration to Done. These are restricted observations; they do not establish arbitrary contextual graph equivalence or general structural conformance.

## Inferred paths and historical admission

An inferred Step owns its supporting Path and concrete application Request. Before projection, the support's initial configuration must equal the current configuration, including frames, occurrences, branch assignments and allocation state. Merely matching printed values is insufficient. Projection checks the endpoint match and applies it back to that source. The outer path records the resulting state, immediate flow and reads while retaining the complete auxiliary derivation inside the step. Composition continues from the outer source, rather than appending the auxiliary endpoint as an ordinary sequential state.

Supports can themselves contain inferred steps. The finite owned representation cannot encode a self-referential support cycle; its leaves are initial configuration premises and checked primitive transitions. Two derivations with equal final states and resource flow can still differ in supporting reads, and remain distinct Paths. This is not a validator for arbitrary external evidence or the native cyclic support graph. Initial configurations, nominal identities and branch assignments remain fixtures; production event alternatives are not automatically translated into those assignments.

[Historical admission](../model/admission.rs) introduces a completed fragment with explicit witnesses naming state positions, owning worlds and resource places in the current path. Each retained read requires exactly one witness. Admission compares the complete recorded occurrence, rejects missing, duplicate and unused witness entries, and traces world ancestry through the checked suffix flows. The historical world must contribute to the selected current world. A read in an unrelated world is insufficient even when both worlds occur in the same recorded configuration.

Historical support does not restore consumption rights. The operation consumes only explicitly selected live occurrences in the current world and creates a fresh output occurrence. A witness at the current state contributes to the immediate read set. Earlier witnesses remain attached to the Historical step with their positions and complete fragment evidence, independently of consuming flow. Mixed current and historical reads preserve both forms of support. Admission checks branch compatibility before restoring contextual dependencies, and the shared introduction publisher validates the prepared environment before changing the state.

The execution fixture inspects Seed, consumes it through Seed-to-A, then introduces and executes constructed A-to-Seed code using the earlier witness. Direct live-witness introduction rejects that same retained fragment. The accepted historical path retains the original read even when the construction consumes nothing and its new occurrence therefore has an empty resource basis. Another fixture performs the intervening rewrite through source inference. Successful replay must retain the auxiliary inference and the historical witness together.

Ten path tests cover nested inference, composition after a prefix, exact source anchoring, equal-flow/different-read supports, historical construction followed by execution, live admission equivalence, mixed reads, multi-step world ancestry, malformed witnesses, stale consumption and branch rejection. The capture regression restores a reclaimed environment and checks reuse on a second introduction. Owned held reads are additionally supported as described below. Qualified publication below also admits witnesses inside retained auxiliary derivations; this does not establish historical support for every native case.

A bare projected Event still omits its supporting path. Use an inferred Step when retaining a derivation. Historical witness positions are local to their owning path; they are not globally portable occurrence addresses. Replay, projection, historical admission, capture import and rewriting remain atomic reference operations. This increment adds no native construction syntax or production budget-accounting claim and does not complete the structural commuting law.

## Archived capture restoration

[Archive](../model/archive.rs) resolves historical nominal contexts to their canonical qualified origins and delegates reconstruction to the shared [materializer](../model/materialization.rs). The materializer discovers complete parent, lexical, declaration and held-value graphs, then allocates every missing frame before mapping references. Captures inside nested rule values and deferred body declarations are remapped; local binders retain their existing activation behavior. Current frames are reused. A context absent from the entire checked history is rejected. This remains a reference operation over the path's nominal configuration premises.

Each restoration or inferred import records an allocated context's Origin: a derivation Address, original context and an original-to-materialized held-resource identity map. The address points to the canonical original frame, including inside nested auxiliary paths, rather than the latest surviving copy. It is relative to the path containing the record; inferred steps prepend their own record position to imported addresses. These origins remain available even if ordinary reclamation immediately removes an unused prepared frame. They describe contextual support independently of the immediate consuming flow. Historical requests still retain their original fragment and read witnesses; restoration does not rewrite or discard that evidence.

Restoration and import records establish which copies came from the same historical context or held occurrence. Subsequent admission finds a surviving representative through those records. The [resource registry](../model/resource.rs) follows checked origin edges across the retained derivation tree, including several auxiliary held identities that projected onto one existing source resource. Equal integers or equal syntax alone add no equivalence edge. If all representatives disappeared, it restores one archived representative for the proven equivalence class. This preserves sharing when old and previously restored fragments are combined, and after repeated reclamation. Distinct captured frames remain distinct unless an actual restoration record connects them. Equal printed declarations do not authorize merging environments.

A held occurrence that still exists, including through a previous restoration, retains its current identity and all current source places after complete value/capture/history comparison. An absent held occurrence receives a fresh metadata identity, shared across restored frames that refer to the same historical resource. Its immediate resource basis is empty; the Origin map and historical frame supply the retained evidence. An empty immediate basis does not mean that the metadata has no historical dependency.

Restoration attaches lexical environments to code without assigning a live world to those restored frames. New executable bodies retain the current execution parent and use the restored environment only for lexical lookup. A declaration return therefore consumes that body's current reserve, not the archive's old reserve. Tests cover both a genuinely absent held resource and one still shared with a live world: restoration does not add a lost held value to a world, and the resulting Done resource depends on Call rather than the archived Secret. This ownership argument concerns the checked operations; arbitrary new fixture configurations are still premises, not proven descendants.

Five archive test families cover lexical execution and return ownership, current-versus-archived held identity, sharing across separately restored frames, cyclic lexical graphs, captures inside held code, repeated reclamation, combining equivalent historical captures, and allocation failure without mutation. Every recorded configuration in the successful families is independently revalidated. The native comparison erases and reconstructs escaped code in the reference, then compares its final values, occurrence sharing and frame count with the existing native escaped-code execution. This checks preservation of that restricted final observation, not native support for historical construction syntax or equality of the two intermediate derivations.

### Temporal provenance

[Transport](../model/transport.rs) now carries archived origins into source-relative path provenance. A Path retains a checked Flow for each prefix. After composing an immediate transition, transport follows each restored frame's Origin to the corresponding historical prefix, recovers its original source frame and adds the held resource's historical basis. Repeated reclamation therefore preserves both original ownership and proven resource sharing. An origin for a prepared frame that was immediately reclaimed adds no nonexistent target entry.

An immediate Record.flow still describes only the adjacent configurations. Its restored frame can have no immediate origin even when the complete Path.flow has a justified original source frame. Folding immediate maps alone does not reconstruct these temporal edges; checking the historical records and their retained prefixes is required. Ordinary Flow.compose remains unchanged. A frame created after the path's source retains no original source frame after restoration, while its held resources can still project to their actual original dependencies.

Two transport test families cover exact consumption, changed captures, held resources shared with current worlds, repeated restoration and complete replay. An unchanged reconstructed closure recovers exact source consumption for a scoped inferred application. Deliberately changing its outer capture preserves only the broader footprint. The escaped-code conformance fixture now compares the complete projected Event before and after erasure/restoration, including configuration and resource/world/frame flow, in addition to its existing restricted native final observation. These comparisons do not establish arbitrary contextual graph equivalence.

### Owned held reads

A Witness now identifies a World or Held place plus its historical owning world. A world place must name that same world. A held place must belong to that world's execution frame at the recorded state. World ancestry and complete value/history equality are checked in either case. Current held reads appear in the immediate read set; past held reads remain explicit witnesses in the retained Historical step. Neither form adds a consuming dependency to the newly introduced value unless the request separately consumes an available live world occurrence.

Four admission test families cover current and historical reserves, mixed world/held reads, malformed places, wrong ownership, unrelated ancestry, altered values, duplicate identity claims and unavailable consumption. Captured code read from a historical reserve executes against its restored lexical declaration after the original frame disappears. The resulting execution depends on its current argument, while the construction step retains the historical code read. A restored archive frame has no live owning world and is rejected as a current held-read owner. The original historical owner remains usable.

These operations remain atomic reference work, and retaining every prefix adds storage and copying cost. Qualified publication below supports construction from auxiliary witnesses and origins reachable inside auxiliary derivations. General grounded proof graphs and the full structural commuting law remain unfinished. No native historical-construction syntax or production progress guarantee is introduced.

## Qualified support lookup

[Support](../model/support.rs) resolves a resource in the retained derivation tree. Its Address contains the sequence of inferred-record positions to descend through and a state position in the selected path. A Request adds the owning world and resource place at that state. Every descent must select an actual Inference record whose child source equals the parent configuration at that position. Invalid descent and state positions produce structured failures. An address is relative to its owning Path, not a globally portable proof identifier.

Resolution retains the original Path, current target world, qualified Request, recorded configuration and complete occurrence. It composes checked prefix flows at every descent to obtain the selected state's resource/world/frame relation to the original path source, including temporal archival edges already validated in those prefixes. Local identities in that relation's target domain belong to the addressed state. A matching integer in a different derivation does not identify the same frame or resource. The full supporting path remains necessary: consuming flow does not replace executable reads or historical support.

Ownership is checked at the addressed state. For an auxiliary witness, resolution transports every contributing world back through the nested source anchors, then checks that all belong to the current selected world's ancestry at the outer anchor. Sharing only one contributor is insufficient. Main-path historical witnesses retain the same suffix-ancestry rule as before. Current main-path reads alone contribute an immediate read place; auxiliary and older reads retain their qualified support. Historical admission now uses this common resolver for its existing main-path witnesses.

Six support test families cover nested derivations, nonzero source anchors, malformed addresses, unrelated and partially overlapping world ancestry, auxiliary held reads, archival transport and independently allocated capture collisions. One family resolves A, B and F at the same world/resource numbers in three different derivations. Another retains two different frames numbered 1: the auxiliary frame owns the inspected closure, while the main frame has different declarations and held resources. A held read succeeds at its earlier owning world and fails after that world returns, even when the captured frame still exists.

Passing a raw auxiliary occurrence to ordinary inspection discards its derivation coordinate; equality of the resulting integers cannot authorize capture import. Qualified construction below retains that coordinate through composition and materializes its graphs through checked publication. Initial configurations and branch assignments remain premises; this resolver does not establish the general grounded proof law.

## Qualified construction

[Qualification](../model/qualification.rs) anchors construction to an owned checked Path and one current target world. Inspection takes a qualified support Request, validates it with the existing resolver and returns a fragment whose code captures retain their derivation origins. Evidence keeps the immutable [proof anchor](../model/proof.rs), complete read requests and recorded occurrences. Main-path and auxiliary reads use the same qualified representation in this mode. Ordinary nominal read and context accessors remain separate; an empty ordinary read set does not imply that a qualified fragment has no reads.

The shared structural types now distinguish the context at the active level from the capture type in deferred declarations. [Reference](../model/context.rs) preserves the distinction between a captured environment and a local binder at either capture type. Qualified values are not accepted by the existing nominal introduction interface.

A [qualified capture](../model/capture.rs) names the context's origin inside its owning proof. Resolution follows a frame inherited from an auxiliary source back to its parent anchor. It follows checked archival restoration links back to the recorded original frame. Otherwise the frame's first occurrence in its own derivation establishes its origin. Independently allocated frames remain distinct even when their numbers and printed declarations match. This origin normalization preserves proven inherited and archival sharing; it does not establish general contextual-code canonical equality. Inferred application now records explicit links to its auxiliary capture origins, which remain available after reclamation and subsequent restoration.

Fragment composition requires compatible histories and the same complete proof anchor, including the selected target world. Equal local coordinates from detached or different paths are insufficient. Qualified reads and capture dependencies survive reconstruction even when a component is replaced. Repeated inspection of one address shares its read obligation, while repeating its syntax remains a description operation with no new resource-consumption right. A capture's address is interpreted together with the fragment's proof; it is not a globally meaningful identifier by itself.

### Executable publication

The existing introduction publisher validates explicit consumption against the actual current world. Historical or auxiliary reserves never create live consumption rights.

The shared materializer reuses surviving capture representatives and allocates missing graphs before resolving cyclic references. It preserves proven resource sharing across main and auxiliary paths. A reused held resource retains its complete current occurrence after qualified value and history comparison; a missing resource receives one fresh metadata identity per proven equivalence class. Parents, lexical links, held code and deferred declarations are remapped together. Local binders remain local. Allocation failure leaves the original path unchanged.

Publication retains the fragment's proof and read evidence in the recorded request, while materialized frames retain canonical addressed origins. Only current main-path reads appear in the immediate read set. Inferred application also retains import origins, and temporal transport composes them through checked auxiliary source anchors. A projected Event still needs its supporting Path to interpret those addresses. Neither a consuming flow map nor an origin map alone is an independent certificate.

Six publication test families cover sibling and main/auxiliary capture collisions, execution against distinct private declarations, reclamation followed by republication, inferred execution, current held reads, unavailable and repeated consumption, detached proof rejection, unrelated world lineage and allocation exhaustion. ## Complete contextual graph comparison

[Comparison](../model/comparison.rs) checks whether two finite Configuration graphs differ only by administrative frame, world and occurrence identities. Success returns a Mapping containing a complete bijection for each identity domain. The root, world ownership, parent and lexical edges, declarations, all live and held occurrences, nested captures and local binder depths must correspond. One occurrence shared between several worlds and frames remains one occurrence; equal fresh values cannot replace that sharing. Cyclic lexical graphs are compared without recursively unfolding environments.

Configuration history and each occurrence's history compare exactly, including branch identities. Atom spelling is literal. Input particles, output destinations, body declarations and frame declarations compare as multisets with multiplicity; declaration vector positions are administrative indexes for this observation. Empty input, one empty input particle, no destination, an empty destination and an empty body remain distinct. All supplied frames and worlds participate, including unused frames and empty worlds. The comparator does not silently reclaim premises before comparing them.

An independent [structural view](../model/shape.rs) traverses rules and deferred declarations, substitutes only external capture identities and sorts at the existing multiset boundaries. It does not call activation, import or publication's renaming implementation. Capture-erased declaration shapes only filter candidate frame assignments; successful comparison always checks the complete shapes under an injective frame mapping. A private [bijection search](../model/bijection.rs) checks parent/lexical edges while assigning frames, then world ownership and complete occurrence incidence across live and held places. This preserves both syntax and graph sharing.

The `find` interface accepts an additional predicate on complete mappings. If one otherwise valid mapping fails that constraint, search tries alternative frame, world and resource assignments. This matters when equal current values have distinct provenance: rejecting the first mapping must not reject another valid flow-preserving correspondence. `compare` selects the first unconstrained graph correspondence. Neither interface mutates or merges configurations.

Eight [comparison test families](../model/test/comparison.rs) cover reversed allocation and declaration order, cyclic lexical links, captures inside held code and nested declarations, distinct local binder depths, changed ownership and sharing, literal histories, all empty boundaries and multiplicity, unused frames, empty worlds and constrained symmetry across all three identity domains. A separate two-world/three-resource incidence calculation checks all 729 pairs of nonempty resource membership patterns. Archival restoration is compared against its original complete configuration through three reclamation cycles, both with an absent reserve and a reserve shared with a live world; the returned mapping is also checked against the actual world/frame/resource flow. Successful restored paths replay and their configurations revalidate.

This is a finite configuration-graph relation, not a canonical key, equality of proof objects or a production bisimulation. It deliberately excludes allocation counters and exhaustion state, derivation addresses, executable read records and proof anchors. Declaration-index references in evidence need their own correspondence check. Equal configuration graphs therefore do not authorize exchanging qualified proof anchors or histories. The search copies candidate mappings and can take factorial time; structural traversal and comparison remain atomic reference work. No performance or production interruption guarantee is claimed.

## Transition boundary provenance

[Transition](../model/transition.rs) owns a checked supporting Path and application Request, computes its projected Binding and applies that projection to obtain an Event. Its fields are private and its constructor returns the existing structured projection/application failures. The retained path is available for subsequent proof comparison; a caller cannot manufacture a Transition by supplying unchecked flow or read sets.

The `boundary` relation jointly searches configuration correspondences at three boundaries: the original source, the auxiliary witness endpoint, and the projected result. It compares every resource, world and frame edge in both the source-to-witness flow and source-to-result flow using the independent [provenance traversal](../model/provenance.rs). The same source mapping must preserve the binding's execution frame, projected owner, selected worlds, footprint, exact subset and executable reads, together with the event's reads, consumption and any surviving owner. Selection preserves world/resource association while permitting multiset order changes. Local code must name the corresponding witness occurrence. A declaration reference must select the same complete contextual rule under source renaming, even when its vector index changes.

Surviving nominal identities must retain their source correspondence in the witness and result; a fresh copy cannot impersonate a continuing resource or frame. The witness and projected result are separate branches, so identities allocated independently in those branches do not acquire a relation just because their integers agree. A complete Mapping exposes the three configuration maps. The constrained `find` interface backtracks through all three searches if a candidate fails the caller's additional condition, rather than committing prematurely to an arbitrary symmetric endpoint match.

Eleven [transition test families](../model/test/transition.rs) cover allocation renaming, reordered declaration references, alternative correspondences for equal occurrences, differing current executable reads, resource/world/frame flow changes, nested inference, scoped held flow, exact versus broader footprint consumption, malformed requests, repeated archival restoration and the auxiliary-support boundary below. An independent two-by-two resource incidence calculation checks all 256 pairs of flow relations under a fixed nontrivial identity mapping. The current-read counterexample has exactly equal event configuration, consuming flow and consumed set; only one application reads a live code occurrence, and boundary comparison rejects it. Scoped tests distinguish unchanged operands that become reserves from transformed operands whose broader source footprint stays live.

Repeated restoration compares complete projected boundaries across successive reclaimed copies, with both absent and live-shared reserves. The original un-reclaimed witness and a reconstructed witness can be configuration-isomorphic while failing this stricter relation because their identity lifetimes differ. This is intentional: graph equality and transition correspondence have different premises. Reconstruction requires an explicit relation and support obligations, such as the conditional law below; it must not silently drop continuity checks.

This increment implements boundary provenance, not recursive proof equivalence. A counterexample keeps two auxiliary paths with equal states and composed flow but a different internal code read. Their transition boundaries compare, while their owned paths and Transition values remain distinct. The relation does not traverse those internal records, qualified proof anchors, historical addresses or import-origin maps. It therefore cannot authorize substituting one support proof for another. The low-level provenance helper compares relations under supplied maps; validation remains the checked Path/Transition constructor's responsibility. The aligned recursive comparison below closes this read-support gap on its stated domain, including transient import metadata. The structural construction/projection law remains required. All correspondence search and projection costs remain atomic reference work.

## Aligned recursive derivation comparison

[Derivation](../model/derivation.rs) compares checked finite Paths with corresponding record positions and step kinds. It returns complete configuration mappings for every state and nested inference branch, with lookup by the existing Address type. Source configurations, all intermediate configurations, immediate transition flows and every composed prefix flow must correspond. Nominal mappings remain injective and consistent across the entire owning path, including after an identity disappears. Each child path's initial mapping must equal its parent's mapping at the exact inference anchor; sibling allocations keep separate namespaces.

The [attestation traversal](../model/attestation.rs) compares every recorded read, consumed place and context dependency. Direct applications compare the selected local occurrence or complete referenced declaration. Inferred applications additionally compare their projected footprint, exact subset, world ownership and reads. Local and inferred selection retains world/resource association. Declaration order can change when the referenced contextual rule corresponds. Search backtracks over intermediate and nested mappings, so an arbitrary first match among equal occurrences does not determine the result.

Introduction compares the complete nominal fragment and evidence. Historical introduction also retains the recorded state, owning world and World/Held place of every witness, with all captured values, resource identities and histories mapped in the owning path's namespace. Qualified construction compares the exact proof-prefix position and selected world, all qualified read addresses and complete recorded occurrences, and every canonical capture address and context. Its independently traversed structural value preserves local binder depth and maps qualified captures without calling activation or publication's renaming code. Import/restoration origins compare their derivation addresses, original frames and complete original-to-copied held-resource maps.

Qualified proof prefixes must actually be prefixes of their respective checked paths. Since the paths' records and nested branches are compared recursively, an equal-length anchor with different internal support cannot pass merely because its endpoint agrees. A successful comparison does not change the stricter exact-anchor rule used by fragment composition or authorize substitution into an existing live proof. Literal histories, initial configurations and checked-path construction remain the premises of this reference relation.

The [origin correspondence search](../model/correspondence.rs) extends each owning path's mapping with imported contexts and copied held resources, including identities allocated and reclaimed within one step. It matches archive entries at corresponding record positions through their exact derivation addresses and the original frame/resource mappings at those addresses. Every extension remains injective and consistent with all configuration mappings and earlier archive entries. Several original held identities may justify one copied resource when both paths retain that sharing; distinct copied resources cannot silently merge. Equal original addresses do not force distinct imported frame copies to merge. Search keeps alternative archive assignments until the complete record checks and caller predicate pass.

`Derivation.identity()` exposes the complete mapping for the owning path, including transient metadata. State mappings and `at(Address)` still describe exactly the corresponding recorded configurations. Child mappings remain separate: a live occurrence in the parent and a transient copy in its child can have the same local number without becoming one identity. The low-level `provenance::origin` relation checks an individual original-to-copied resource map under supplied correspondences; as with the flow helper, it does not independently validate a caller-supplied archive or establish reachability.

`compare` and constrained `find` return `Ok(Some(mapping))` for correspondence and `Ok(None)` for a mismatch within the supported domain. Application, introduction, historical, qualified-construction and nested-inference records now support both recorded representatives and checked transient import origins. `Err(Unsupported)` retains a guard for a context dependency with neither a configuration representative nor an origin in that record; it identifies the side, derivation address and context. No such remaining case is demonstrated by the current checked-path fixtures. Different path lengths, step kinds or witness positions are mismatches under this aligned relation; equivalence after reordering or contracting steps is outside its claim.

Successful execution fixtures replay and their configurations revalidate.

A [Transition](../model/transition.rs) can now `retain` its projection as an actual checked inferred Path. Comparing those retained paths includes the auxiliary derivation and projected import origins; comparing only `boundary` remains the intentionally weaker observation. The search copies configurations' correspondence maps and recursively enumerates alternatives. It is atomic reference work with potentially factorial cost, not a production progress guarantee or an external reachability-certificate checker. The construction/projection law remains open.

## Reconstruction through projection

[Reconstruction](../model/reconstruction.rs) adds a checked transformation of a Transition selecting a local executable. A supplied qualified fragment must exactly reconstruct that executable's complete value and evidence at the current witness. Publication consumes the original executable and emits a fresh one; the application request follows the changed world and code occurrence. The transformation retains the entire original supporting path as a prefix. A nominal-value check rejects capture normalization that would change the complete rule seen by matching. Declaration references and exhausted reconstruction allocation remain outside the admitted operation.

The [reconstruction audit](reconstruction.md) states the two paths, exact support extension, preserved observations and written preservation argument. Template input/output binding and suspension-prefix checks preserve the complete reconstruction fragment. The matrix reconstructs twice under sixteen combinations of operand transformation, destination shape and nominal allocation.

This is an exact-reconstruction law with explicit premises and bounded reference evidence, not completion of the general structural construction/projection law. Read-only publication can change projected executable reads; reconstructing shared code can change the intermediate witness graph while preserving the projected Event. Tests retain these counterexamples and do not weaken aligned proof comparison. Changed-shape template construction from projected bindings remains next, with separate rules for code description, captured references and transferred live occurrences. Initial histories/configurations, external grounded support and production accounting retain their existing boundaries.
