Molten runtime plan

Rules transform concrete information. A derivation can reveal that a rule applies at an earlier source. That source gains an alternative outgoing event; intermediate descriptions do not become extra operands. Coherences evolve independently, and only a joint derivation can justify bringing them together.

This laboratory integrates concrete-source inference, multiple outputs, nested bodies, conditional support, and state sharing in one finite reference evaluator. It also executes finite ground generated rule values, whole-rule abstractions, lexical captures, and conditional rule availability. The 26 program examples use this same evaluator.

One evolving graph

A state is an orderless collection of coherences with their live occurrences, lexical environments, and return continuations. Occurrence identity records sharing: two copies of an inherited reference can denote one introduction, while two independently computed equal results remain two introductions. Particle multiplicity remains significant: A.A differs from A.

An event records a rule, its concrete binding, its result configuration, and its justifications. Direct matching is the identity derivation. An inferred match uses the same application operation, with a joint witness projected to a concrete footprint. Repeated evidence contributes support to the same event. It does not emit another copy of its result.

OperationConcrete behavior
Literal resultReplace the projected source footprint. Preserve unrelated source remainder.
Nested bodyConsume exact source matches; transfer the remaining concrete witness and unrelated remainder into the body. Record consumed context in its continuation.
Several outputsCreate fresh explicit results. Broadcast references to the combined remainder into each output coherence.
DecoherenceRequire one joint witness. Reconcile shared untouched introductions once; retain independent introductions separately.
State reuseCanonicalize occurrence names, coherence order, sharing, scope, and continuation. Reuse equal configurations while retaining distinct event support.
Conditional applicationRecord dependencies explicitly. Unresolved absence remains conditional; bounded failure to find evidence is not proof of absence.

A consequential choice: with A → B.C and B → D, inferred application at A produces D; actual sequential execution produces C.D. These are distinct alternatives. Source inference is an additional language operation, not a claim that every evidence path can be replaced by an observationally equivalent shortcut.

Likewise, a joint match of sibling B and C can project to their one producer A. It need not invent two copies of A. Separate competing paths A → B and A → C cannot supply that joint witness.

Matching gates


A gate is a useful implementation picture: partial matches arrive, compatible assignments accumulate, and a completed assignment enables an event. This resembles the incremental matching networks described by Forgy. His paper also describes count-based filtering and explains why retaining matched elements and their combinations avoids repeated whole-memory scans. Forgy, Rete (1982), §§1.2–2.


A semaphore counter is insufficient as the matching representation. For And.Boolean.Boolean, the two Boolean positions must receive two distinct current occurrences from a compatible witness. Receiving the same proof twice cannot fill both positions. Different substitutions, scopes, and incompatible histories must never be added into one count.

The reference now uses incremental gates for coherence input positions. Each gate belongs to one joint witness configuration and frame; it retains slot candidates and compatible prefixes, including out-of-order arrivals. Completed bindings feed the existing source projection and event interning. Particle matching still enumerates literal occurrences. Lazy matching gates are cached by target configuration, frame, and pattern, sharing bindings across views. Incoming/outgoing dependency indexes avoid repeated full-graph scans. Parallel worker synchronization is not implemented. The production design should index candidates by rule value, source configuration, scope, substitution, and occurrence assignment. Maintain a set of filled positions for each compatible partial binding; a count can summarize that set. Reverse dependencies wake eligible concrete sources when evidence changes. Notifications travel through an index; recorded history is never physically rewritten.


Matching, propagation, and application remain one iterative semantic relation. An implementation may pipeline their bookkeeping and use queues or synchronization primitives without introducing a language-level search/commit phase. A fair queue processes newly discovered bindings and support changes. Unchanged candidates do not pulse forever.

Rules as values


Exact matching needs no decomposition. A complete nested rule can occupy one ordinary pattern position. Match the whole value, consume that occurrence, and produce the output by the same operation used for any other concept. Accessing a rule’s internal fields is needed only for a pattern that explicitly asks to match those fields. Being internally structured does not make a value multiple operands.


Implemented reference contract: represent a rule as an immutable structural value with its lexical bindings. Ordinary rules may match such values and produce new ones. The active rule index is derived from the rules visible in the current configuration; it is an optimization, not a separate global mutable program.


The chemical abstract machine gives a precedent for unordered reaction-based computation and a higher-order calculus. The join-calculus tutorial develops reaction definitions and lexical scope in a precise concurrent model. These are useful precedents for a small operational core, not evidence that Molten’s proposed source-inference semantics already follows from either calculus. Berry and Boudol (1992); Fournet and Gonthier (2001 draft).


The notation below is explanatory, not Molten surface syntax. rule(P,Q) denotes a structural rule value; the brackets in [[A,B]] ([B]) do not yet have a settled executable interpretation.


R = rule(A, B)
M = rule(R, rule(A, C))

current:   { A, R, M }
rewrite:   { A, rule(A, C), M }
apply:     { C, rule(A, C), M }


The accepted interpretation is ordinary consuming replacement: M explicitly matches the rule value R and replaces it in the successor. The earlier state still exists and may have its original alternative A → B. This is local program evolution. A global alias that makes two expressions interchangeable everywhere would be a stronger semantic commitment.

The generated-rule tests distinguish read support from consumption. Seed.A can infer Seed.B when Seed produces A → B; if one Seed produces both the rule and A, inference consumes Seed and produces B. The executable examples below include both cases, conditional code, rule replacement, whole-rule abstractions, and escaped lexical captures.


The reference supports finite ground rule constructors. It does not implement arbitrary unknown subterm extraction, behavioral equivalence, or executable textual lowering. Structural rule-code equality and capture-aware configuration identity are explicit and tested.


Implemented semantic decisions


The closure contract records the accepted reasoning and acceptance matrix. The finite dynamic reference now implements the core interactions together. The distinction between that milestone and production work is listed below.


One event, explicit dependencies


Invoke a rule by reading its availability. Consume a rule value only when a pattern explicitly matches it as an operand. Track consuming footprint C separately from read support R. A literal inferred result removes C and preserves the concrete source outside C, including R minus C. If one source supplies both roles, consumption wins.

These results are generated by the first three dynamic examples in the program selector. Read support is historical enabling evidence: consuming Seed later must not erase B. A later defeat of an absence assumption can change support, which is a different relationship. A nested frame retains its executable closure without inventing a consumable R or turning its read dependencies into held consumption.


Rules remain local values


Expose a produced rule in an active coherence or lexical environment to make it eligible. Its rule value and arguments must have a compatible joint witness. A coherence supplying only read support stays in place; only input-bound coherences contribute leftovers. This preserves the parallel-context contract.


Capture immutable defining environments. Moving code preserves that capture; invoking it supplies a separate return continuation. Replacing a definition creates a successor value or environment, leaving historical closures intact. Canonical identity includes code, captures, sharing, and multiplicity. It never attempts to decide arbitrary equivalence of rule behavior.


Abstractions remain computation


Keep whole-value matching primitive. A rule can derive an abstract description of another rule and apply that description at the concrete source through the same mechanism used for True → Boolean. No mandatory decomposition or separate meta pattern matcher is required. Arbitrary structure extraction still needs explicit program-expressible operations; whole-value matching alone does not prove those operations exist.


Absence tracks its assumptions


The reference disables the fixed-rule label certificate whenever rule values occur. Dynamic queries remain open during exploration and resolve through supported evidence or finite completion. A generated route to Q can defeat an absence-dependent result; conditional code remains conditional. Early component-local certificates and incremental edits to closed models are production work, not silently assumed capabilities.


Source notation must distinguish value and body


Require an explicit output for a complete rule value in the first executable grammar. Keep input-only bracket forms provisional until they have an unambiguous constructor interpretation. Returning a rule value and entering a body must lower to different existing expression forms; successful parsing of [[A,B]] ([B]) does not decide which was intended. The structural representation now distinguishes and executes those forms explicitly: {particle: [{rule: ...}]} returns code, while {body: [...]} enters a body. Textual lowering remains to be implemented.


Execution follows the reference


Use persistent dependency indexes and binding gates behind one fair agenda. Start with deterministic execution; parallel workers can compute deltas against immutable snapshots and merge them through idempotent state, event, and support interning. Hashing may accelerate equality checks but cannot replace exact comparison. Require differential tests against the reference before making a performance or parallel-correctness claim.


Reference milestone complete: generated-rule availability, read/consume projection, lexical capture, conditional support, and whole-rule abstraction now execute together. Semantics and implementation boundaries


The reference evaluator uses complete configurations to prevent accidental mixing of competing histories. Relative flow maps connect witness occurrences to source occurrences. Canonicalization preserves sharing while renaming anonymous introductions. Fresh equal outputs remain distinct, but a finite A ↔ B cycle shares two configurations.


Absence uses explicit support dependencies. For programs without rule values, a conservative label-reachability invariant can certify some impossible queries before all computation finishes. Otherwise an unfinished query remains open, and finite agenda completion can establish absence in this ground model. Recursive negative dependencies remain conditional; optional stable interpretations illustrate alternatives without rejecting programs that have none. This treatment is informed by SWI-Prolog’s well-founded semantics documentation.


The intended completeness claim is fair discovery of every finite enabled derivation with sufficient resources. It is not guaranteed termination or a decision procedure for arbitrary absence. The laboratory limits state count, coherence count, live resources, frame count, and scheduled work; reaching a limit leaves deferred work available for resumption.


The finite reference is deliberately exhaustive. It now has structural code interning, lazy matching caches, and adjacency indexes. Symmetry enumeration and whole-clause support evaluation remain bounded reference techniques; canonical graph refinement and component-local support maintenance are the production direction. Any such optimization must preserve the reference’s observable events and support, including alternative paths that source inference makes distinct.


Physics motivates locality and explicit causal accounting. It does not uniquely select this rewrite algebra, determine whether rules are persistent, or prove the source-projection convention. “Coherence” and “decoherence” are Molten terms; the model does not implement a quantum state space or physical quantum decoherence. Configuration and event-structure research supplies the more direct mathematical comparison for joint availability and causal alternatives. van Glabbeek and Plotkin (2009).


The Rust implementation currently provides a structural syntax frontend and a separate generic rule kernel. Its exact matcher also accepts rules as its concept values, including rules containing rules; a regression test exercises this without a meta evaluator. This proves exact nested value replacement, not runtime activation or behavioral equivalence. Rule ordering in this low-level API is representation ordering, with input/output vector positions retained. It does not execute this integrated graph or higher-order rules. The old source laboratory remains useful for earlier examples; this configuration model supersedes its single-result ownership assumptions.
